# Достижимость событий доказанных correspondences

VERIFIED EXPERIMENTALLY для трёх ограниченных inputs; перенос существования trace на исходную репликацию обоснован ниже. Это дополнение к первоначальным 24 запускам после повторного указания пользователя продолжить работу.

| Доказанное свойство в исходной модели | Положительное свидетельство | Событие |
|---|---|---|
| A6, reg_client/getToken, E0 (R04) | W-reg-E0 | Server_Finish_Reg |
| A6, reg_client/getToken, E2 (R06) | W-reg-E2 | Server_Finish_Reg |
| A1, auth_client_em/getToken, E0, preciseActions=true (P-A1-E0) | W-auth-E0 | Server_Finish_Auth |

## Что именно проверено

В `experiments/configs/witnesses.yaml` описаны три D-finish. `single_session_witness: true` — собственная диагностическая настройка надстройки, не флаг FIDO2Verif. После вызова исходного генератора в отдельной копии один корневой `!system(` заменяется на `system(`. При отсутствии или дублировании маркера генерация завершается ошибкой. Криптографическая библиотека, остальные процессы, каналы, таблицы и сообщения не меняются. Настройка `preciseActions=true` — официальная настройка решателя ProVerif.

Каждый input завершился меньше чем за 0.12 s с `RESULT not event(Server_Finish_...) is false.` и `A trace has been found.`. Ни один не содержит `assuming the following hypothesis`. В trace регистрации видны Authnr_Finish_Reg и Server_Finish_Reg с согласованными аргументами, в trace аутентификации — Authnr_Finish_Auth и Server_Finish_Auth. Значение false здесь означает достижимость, а не уязвимость.

## Почему это снимает вакуозность

Unbounded security proofs и bounded witnesses решают разные задачи. A6/A1 уже доказаны в исходных моделях с `!system`. Чтобы исключить тривиальное выполнение correspondence из-за недостижимости события слева, достаточно показать хотя бы одно допустимое выполнение до этого события.

Репликация допускает развёртывание одной копии system; остальные копии не обязаны выполнять шаги. Любое конечное исполнение единственной копии из witness-модели тем самым является допустимым исполнением исходной реплицированной модели, с точностью до переименования свежих имён. Следовательно, найденные положительные traces устанавливают достижимость antecedent-событий в соответствующих исходных конфигурациях.

Этот аргумент не переносит отсутствие атак, секретность или недостижимость из bounded-модели на unbounded. Если бы single-session запрос оказался true/UNKNOWN, вопрос достижимости исходной модели остался бы открытым. Код запрещает применять этот режим к A6/A1/S-pintok и другим security queries.

## Проверяемость и пределы

`tests/test_witnesses.py` сравнивает каждый новый input с уже сохранённым unbounded диагностическим input: восстановление одной `!` возвращает byte-for-byte исходный PV; библиотеки идентичны. Тесты также проверяют, что hypothetical trace не маркируется подтверждённым witness.

Старые D-reg_client-E0/E2 и D-auth_client_em-E0 остаются UNKNOWN/timeout: их результаты не переписаны. Новые inputs имеют отдельные IDs, raw metadata и SHA256. В processed summary поле interpretation указывает REACHABLE_SINGLE_SESSION_WITNESS. Из пяти ATTACK_OR_FALSE в общем наборе из 27 запусков только один является контрпримером A6; остальные четыре — положительные проверки достижимости.

Это снимает ограничение невакуозности именно трёх доказанных конфигураций проекта. Оно не доказывает достижимость всех возможных ветвей, соответствие современным спецификациям или безопасность реальных реализаций.
